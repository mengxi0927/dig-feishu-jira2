# Jira 派工日志、财务锁期与补录

## 已确认规则（2026-09-23）

- 北京时间每天06:00运行，截止日期为昨天。保留最近30天回溯，以发现近期新增、修改、删除；未结算期间超过30天时覆盖完整期间。查询中出现原有来源消失时，扩大到本年核对。
- 每月22日同一任务改为核对当年1月1日至昨天。漏跑后由下次任务补做，不并行重复启动月度任务。去年补录不追溯。
- 财务期间为上月22日至本月21日，以北京时间22日零点锁期，不依赖上次任务是否成功。9月23日发现9月21日及以前的变化走补录，9月22日起走正常表。
- 正常周期的新增、修改、删除按现有日期＋项目号＋姓名算法重新汇总“工时信息”，保留日粒度来源与四位小数舍入。
- 已锁期的变化在每次同步发现时立即写入补录，不等22日。增加5→8写+3，减少8→5写-3，删除5写-5，跨期新增5写+5。后续8→6再写-2，累计差额与最新Jira一致。
- 项目、人员、日期变更按旧归属扣除、新归属增加，分别判定锁期。
- 30天以外的变更通常在月度核对时发现；每日调度不是实时事件监听，不查询未来工时日期。

## 三张表及来源字段

- Jira同步表格-派工追加新增／修改／删除日志；保留allocationId、dateCreated、dateUpdated。已有历史原始记录保留，后续日志通过“变更事件ID”防重。
- 三表“派工识别id”为allocationIdYYYYMMDD，例如8292320260921。正常表汇总多个来源时，去重排序后逗号分隔。后台来源键仍为allocationId|day，不因显示格式变化而改变。
- 正常工时和补录表不要求allocationId字段。“派工日期”（兼容旧名“日期”）是实际工时归属日期；不额外创建一个空的“日期”字段。
- 补录工时写入“补录工时（小时）”，不写入原“工时（小时）”。“派工录入日期”取dateCreated的北京时间日期；删除取历史快照创建日期，未知不填同步日期。
- 来源日明细ID不是变更事件ID；同一来源可能产生多次差额。补录使用“同步明细键”防重，日志使用“变更事件ID”防重。

## 月表

每月22日建立工时信息-补录-x月；该月此前已有跨期差额时提前创建。按发现／处理月份记入月表，不按实际派工月份倒填旧月表。状态按YYYY-MM登记table ID，首次启用年份之后表名附年份防重。

2026年9月复用已整理的补录表，不因人工改名另建重复表。新月表复制模板字段并重映射本表公式引用；查找引用按飞书API能力转等价公式。视图、权限和自动化不会随字段复制。

技术字段“调整期间”记录处理年月。模板“派工区间”现有公式曾按26日切月，程序不擅自重写财务公式；如用于下游结算，须统一口径，不能用动态TODAY公式代表已关账状态。

## 已完成历史分类的接入

历史首次归类按创建日期所在财务期间判断：实际派工日期早于该期间首日为跨期新增；提前安排未来日期不算逾期。不能把全年数据一律正常导入，也不能把同步当天看到的全年历史全额补录。

2026-09-23核查截至当天导入快照：9234条来源日明细，1266条跨期新增（8777.2小时）已转入9月补录；正常表7339行、53288.4999小时。旧-12小时临时聚合调整已备份后由完整明细替换；合计62065.6999小时不变。

38个派工（73条日明细）创建时正常、最后修改在关账后，缺历史旧值，单列待核查。不能依据dateUpdated把当前全额当修改差额。接入后以已核对的当前余额为未来差额基线，保留这份历史待核查清单，不声称旧差额已结清。

接入命令：

```
node src/cli.js adopt-classified --snapshot /app/data/year-baseline-20260923/source.json
```

必须存在历史分类审计标记。程序逐条核对正常表金额／识别ID、补录金额／日期／姓名／项目／录入日期，全部一致才建立observed/accounted；不重写工时、不重复补录。重复初始化或来源不符时拒绝。技术字段在核对通过后补齐。原initialize仍用于尚未拆分且正常表完整匹配的旧基线，不能用于已分类历史。

## 持久化与失败恢复

STATE_FILE中的assignment包含：

- observed：上次完整观察到的来源日明细。
- accounted：已经计入正常工时或补录的来源余额。
- closedThrough：已核对的关账截止日；锁期边界由当前日历独立计算。
- months：每月补录表ID、名称、字段准备状态。
- pending：写远端前落盘的待执行批次。
- historicalUnresolvedKeys：接入前仍缺历史依据的修改明细。

写入由唯一生产主机及文件锁保护，派工与报工任务串行。日志／补录按远端唯一键恢复“请求成功但响应丢失”；正常表按原汇总键更新、回读核验。全部成功才推进accounted，重试不吞掉差额。

失败批次可在同一财务期间重放。跨越锁期时停止自动重放，要求先核对部分写入结果，避免旧批次覆盖财务已导出的数据。月度及有补录的批次保存assignment-snapshots快照，与状态一起备份。

## 部署与验证

生产应配置ASSIGNMENT_STRATEGY=monthly-delta、ASSIGNMENT_SCHEDULE_ENABLED=true。旧legacy策略不具备锁期分流，不能在启用新策略后继续写相同业务表。

发布顺序：备份配置、状态、三张表；运行测试；停止旧服务；用新版本接入已分类基线；启动新服务并核验健康状态、北京时间下次06:00触发时间和同步预览；执行一次当前合法截止日同步验证防重。

测试覆盖锁期日／漏跑／跨年范围、增减删与跨日期移动、创建日期取值、归类与未知日期阻断、重试防重、正常表合并不变、历史分类余额接入、日期字段改名、月表创建及连续差额。
